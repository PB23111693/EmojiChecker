# 表情符号课堂情绪检查器系统需求规格说明书

## 1 项目概述

### 1.1 背景与目标

系统面向课堂教学反馈场景，通过学生主动提交表情和 AI 匿名采集表情分类结果，帮助教师了解课堂反馈、调整教学节奏。管理员负责用户、课程、课堂名单以及数据统计与导出。

本文规定系统的功能、业务规则、数据、接口和质量要求，作为项目设计、开发与验收的统一依据。

### 1.2 系统范围

系统由 Web 端、PC 桌面客户端、后端服务、关系型数据库和独立 AI 推理服务组成，提供以下能力：

- **学生端**：注册、登录、修改密码、提交课堂表情、查看个人历史。
- **教师端**：仅访问所授课程，查看课堂和学生的表情历史、实时看板及多维统计。
- **管理端**：访问全部业务数据，管理用户、课程、课堂和名单，查询全部记录，查看统计、导出 CSV。
- **AI 服务**：读取摄像头或本地回放，进行人脸检测、表情分类和置信度过滤，向后端上传结果。

### 1.3 术语含义说明

| 术语 | 含义 |
| --- | --- |
| 课堂 ClassSession | 课程在指定班级、教室和时间段的一次授课 |
| 课堂名单 ScheduleUser | 允许向该课堂提交反馈的学生集合，表示提交资格 |
| MANUAL / AI | 学生主动提交的记录 / AI 服务上传的匿名记录 |
| 时间片 | 限制同一学生在同一课堂重复提交的时间分段，默认 30 秒 |
| FR / NFR | 功能需求 /  非功能需求的编号 |

## 2 用户与运行环境

### 2.1 角色及权限

| 角色 | 主要操作 | 数据范围 |
| --- | --- | --- |
| 学生 | 注册、登录、修改密码、提交表情、查询历史 | 已安排课堂及本人手动记录 |
| 教师 | 注册、登录、修改密码、课堂查询、学生明细、看板和统计 | 本人所授课程|
| 管理员 | 账号操作、用户管理、排课与名单、记录查询、看板、统计、导出和审计查询 | 全部业务数据 |
| AI 服务 | 获取课堂配置、采样推理、上传结果 | 授权设备与指定课堂 |

### 2.2 运行环境与架构

| 项目 | 说明 |
| --- | --- |
| 后端与数据库 | Python 3.12、FastAPI、SQLAlchemy、SQLite WAL |
| Web 端 | Vue 3、Element Plus、ECharts；通过浏览器访问 |
| 桌面端 | Python tkinter 和 urllib，通过 REST API 访问后端 |
| AI 服务 | Python、OpenCV、ONNX Runtime，支持 CPU 推理及摄像头、回放输入 |
| 混合架构 | Web 构成 B/S 通道，桌面端构成 C/S 通道，各端统一访问后端 API |
| 修改版 MVC | 客户端按 MVVM 职责组织，管理端分离视图、控制器和模型；后端采用 Controller → Service → Repository 分层，AI 独立运行 |

各端只通过接口访问业务数据，数据库由后端统一管理。角色校验、数据归属和业务规则均在服务端执行。

## 3 功能需求

### 3.1 账号与用户管理

**FR01 注册、登录与修改密码**

- 学生可公开注册，填写用户名、密码和可选邮箱；教师、管理员凭各自邀请码注册，入口由部署配置控制。
- 用户名唯一，3—32 位、字母开头，仅含字母、数字或下划线；密码为 8—64 位且同时包含字母和数字，采用 Argon2id 加盐哈希存储。
- 登录后返回 JWT 和到期时间；每次请求验证账号状态和令牌版本。修改密码须验证原密码，新旧密码不得相同；修改密码、启用或停用账号后，旧令牌立即失效。

**FR02 用户管理**

- 管理员按角色、状态和关键字分页查询用户，创建教师或学生，启用或停用账号。
- 系统保护当前操作账号和最后一名启用管理员，禁止将其停用；停用账号保留历史关联。

### 3.2 课堂安排与学生反馈

**FR03 课程与课堂管理**

- 管理员创建课程并指定一名启用教师，同一教师下课程名唯一；课堂包含课程、班级、教室、起止时间和 AI 阈值。
- 课堂按服务器时间显示未开始、进行中或已结束；有效区间为 `[开始时间, 结束时间)`，结束时间须晚于开始时间。
- AI 阈值取值 0—1，默认 0.6；课堂开始前可修改信息或取消，开始后课堂信息、名单与阈值冻结。

**FR04 课堂名单管理**

- 管理员为指定时间的课堂批量安排学生，在事务内整体保存名单并去重。
- 名单决定提交资格，课堂开始后不得修改名单。

**FR05 学生提交表情**

- 已登录且在名单内的学生可向进行中课堂提交表情；系统明确提示提交结果和服务器记录时间。
- 支持七类表情：

| 表情类别 | 显示名称 | 符号 |
| --- | --- | --- |
| HAPPY | 开心 | 😄 |
| NEUTRAL | 平静 | 😐 |
| SAD | 低落 | 😢 |
| ANGRY | 生气 | 😠 |
| SURPRISED | 惊讶 | 😲 |
| FEARFUL | 害怕 | 😨 |
| DISGUST | 厌恶 | 🤢 |

- 同一学生、同一课堂、同一时间片最多一条记录；`MANUAL_SLOT_SECONDS` 默认 30，设为 0 时不限制。
- 请求提供事件编号、课堂和表情；学生身份、来源 MANUAL 和观测时间由服务端确定。
- 相同事件编号与内容重试时返回原记录，不重复写入；并发冲突后重新确认事件，课堂结束后仍可查询已成功事件的提交结果。

**FR06 学生个人历史**

- 学生仅查询本人手动记录，不能查看他人记录，AI 记录不进入个人历史。
- Web 页面支持课程、日期筛选及课堂关联查询；历史接口支持班级筛选；记录按观测时间倒序分页。

### 3.3 记录查询与统计

**FR07 教师课堂与学生查询**

- 教师查看所授课堂的反馈历史、反馈次数和参与学生，并从参与学生列表进入手动记录明细。
- 看板和统计限定所授课程，无法访问他人课堂。

**FR08 实时课堂看板**

- 看板按手动和 AI 分区，展示以下内容：

| 分区 | 指标 |
| --- | --- |
| 手动反馈 | 反馈次数、参与学生数、名单人数、覆盖率、类别分布 |
| AI 观察 | 有效观察次数、类别分布、课堂阈值、最近有效样本时间 |
| 公共信息 | 课堂状态、时间趋势、最近更新时间及参与学生明细 |

- 新记录入库后，WebSocket 推送变更信号并触发查询；页面可见时每 3 秒轮询，离开页面停止轮询，切换课堂时丢弃过期响应。


**FR09 多维统计**

- 教师和管理员按权限查询，以课程、课堂、班级、时间、来源和表情类别组合筛选；展示记录总数、手动次数、AI 次数、参与人数、类别分布及时间趋势。
- 看板类别占比按来源分别计算；多维统计占比按当前筛选记录总数计算，支持筛选单一来源。AI 次数为观察次数，同一人跨帧可重复计数，不作为参与人数。


**FR10 管理员记录明细**

- 管理员分页查看全部手动和 AI 记录，按课程、班级、日期、来源和表情筛选，条件与统计保持一致。
- 明细显示观测时间、课程、班级、学生、表情、来源、置信度、设备和事件编号。

**FR11 CSV 导出**

- 仅管理员可导出，沿用统计与明细的筛选口径。
- 字段包含记录 ID、课程、班级、课堂开始时间、学生账号、表情、来源、置信度、观测时间、接收时间和设备；AI 学生列按匿名处理。
- 使用 UTF-8 BOM，正确转义引号、逗号和换行；以 `= + - @`、制表符或回车开头的文本前置单引号，防止 CSV 公式执行。

### 3.4 AI 服务与桌面客户端

**FR12 AI 采集、推理与入库**

- 处理流程：摄像头或回放输入 → 帧采样 → 人脸检测 → 表情分类 → 置信度过滤 → 七类映射 → 关联课堂 → 后端 API 入库。
- 使用 YuNet 检测人脸、MobileFaceNet 表情模型分类；七维输出经 softmax 后选择最高得分类别。采样间隔可配置，默认 3 秒。
- 使用独立 `X-AI-Service-Key` 获取配置和上传，校验设备授权。事件包含编号、课堂、表情、观测时间、来源 AI、置信度、设备与模型版本。

**FR13 桌面客户端**

- 提供登录、选择课堂、提交表情、查看历史和修改密码，与 Web 共用 REST API 和业务规则；仅学生可向进行中课堂提交。

### 3.5 安全与系统支撑

**FR14 权限校验与审计**

- 服务端强制校验角色、数据归属、枚举、时间、分页、置信度和输入格式；数据库使用参数绑定，登录与提交接口限流。
- 审计记录注册、登录失败、创建用户、账号启停、创建课程、创建或修改课堂、保存名单、导出等关键操作；仅管理员可查询，不记录密码、密钥或原始人脸数据。

**FR15 初始化与部署支撑**

- 提供 `.env.example`、初始化脚本、README 和部署说明，支持本机或局域网启动后端、Web、桌面端与 AI 服务。
- 初始化脚本支持生成演示数据和刷新课堂时间。

## 4 数据需求

###  核心实体与关系：

| 实体 | 主要数据与约束 |
| --- | --- |
| User 用户 | ID、唯一用户名、密码哈希、角色、邮箱、状态、令牌版本、创建时间 |
| Course 课程 | ID、课程名称、教师 ID；一名教师可授多门课程，同教师下课程名唯一 |
| ClassSession 课堂 | ID、课程 ID、班级、教室、起止时间、取消标记、AI 阈值；一门课程含多节课堂 |
| ScheduleUser 名单 | ID、课堂 ID、学生 ID、安排时间；学生与课堂多对多，课堂与学生组合唯一 |
| EmojiRecord 记录 | ID、唯一事件编号、课堂 ID、学生 ID、表情、来源、置信度、设备、模型版本、观测及接收时间、手动时间片 |
| AuditLog 日志 | ID、操作者、动作、目标、结果、详情、时间 |

反馈必须关联课堂；手动记录关联学生，AI 学生为空且置信度必填，取值 0—1。事件编号为唯一字符串并作为幂等键，实体采用整数主键，枚举和外键具有约束。

## 5 接口需求

系统采用 REST/JSON，业务接口前缀为 `/api/v1`；WebSocket 使用独立路径。

| 类别 | 代表接口（省略业务前缀） | 权限 |
| --- | --- | --- |
| 认证 | `POST /auth/register`、`POST /auth/login`、`PUT /auth/password` | 注册按角色规则，修改密码须登录 |
| 用户 | `GET /users/me`、`GET/POST /admin/users`、`PATCH /admin/users/{id}/status` | 本人信息或管理员管理 |
| 课程课堂 | `GET /courses`、`GET /sessions`、`POST /admin/courses`、`POST /admin/sessions`、`PATCH /admin/sessions/{id}` | 查询按角色，管理仅管理员 |
| 名单 | `GET/PUT /admin/sessions/{id}/members` | 教师按归属可查，管理员可改 |
| 表情记录 | `POST /emoji`、`GET /emoji/history`、`GET /sessions/{id}/students` | 学生提交，查询按角色范围 |
| 看板统计 | `GET /dashboard/realtime`、`GET /statistics` | 教师与管理员，限制数据范围 |
| AI 服务 | `GET /ai/context`、`POST /ai/emoji-results` | 独立服务密钥及设备校验 |
| 导出审计 | `GET /admin/emoji/export`、`GET /admin/audit-logs` | 仅管理员 |
| 实时通知 | `/ws/dashboard` | 令牌及课堂访问校验，推送变更信号 |

用户采用 JWT，AI 服务采用独立密钥。普通接口统一响应 `{code, message, data, request_id}`，CSV 返回文件流；HTTP 401 表示认证失败，403 无权限，404 对象不可见，409 业务冲突，422 参数错误，429 请求限流。

## 6 非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR01 | 实时性 | 新记录触发看板刷新，推送断线时通过每 3 秒轮询更新；更新时间可见 |
| NFR02 | 易用性 | 学生登录后按进入课堂、选择表情、确认提交完成反馈；状态、错误、空数据和图表含义清楚 |
| NFR03 | 安全性 | 密码加盐哈希、JWT 和角色授权、输入校验、参数绑定、接口限流、CSV 注入防护 |
| NFR04 | 隐私性 | AI 默认匿名，图像仅内存处理；日志不记录密码、密钥，源码不含真实密钥和原始人脸数据 |
| NFR05 | 一致性 | 同一事件只写入一次，名单和时间片约束有效，身份来源不可伪造，查询与导出口径一致 |
| NFR06 | 可靠性 | 网络错误有提示，AI 有限重试，刷新失败保留旧值，桌面网络请求不阻塞界面 |
| NFR07 | 可维护性 | 视图、控制器、业务逻辑、数据访问分离，AI 独立，接口集中管理，错误可由请求编号追踪 |
