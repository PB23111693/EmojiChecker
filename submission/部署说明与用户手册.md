# 表情符号课堂情绪检查器系统部署说明与用户手册

## 1 使用范围与准备

本文说明 Windows 本机及局域网部署、学生和教师操作、管理员管理以及 AI 服务运行。系统使用 SQLite，Web、桌面端和 AI 服务连接同一后端。

| 环境 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11 |
| Python | 3.12，安装时包含 tkinter |
| Node.js | 20 或以上，用于安装依赖和构建前端 |
| 浏览器 | Chrome、Edge 等现代浏览器 |
| AI 输入 | 可用摄像头，或本地回放视频 |
| 网络 | 安装依赖和下载模型时可访问相应下载源；准备完成后可在本机或局域网运行 |

以下命令在 PowerShell 中执行。每次打开新终端，先进入项目根目录；项目放在其他位置时替换路径。

```powershell
Set-Location -LiteralPath 'D:\Homework\软件工程实践\EmojiChecker'
```

## 2 安装与启动

### 2.1 创建环境并安装依赖

首次安装时在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt
.\.venv\Scripts\python.exe -m pip install -r .\ai-worker\requirements.txt
```

后续命令直接使用虚拟环境中的 Python，无需先激活环境。桌面界面使用 Python 自带 tkinter。

### 2.2 配置后端

仅在 `.env` 不存在时复制样例，随后编辑项目根目录的 `.env`：

```powershell
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
```

| 配置项 | 设置方法 |
| --- | --- |
| `SECRET_KEY` | 填写随机长字符串，用于签发用户 JWT；固定保存，重启后继续使用 |
| `DATABASE_URL` | 使用 `sqlite:///./data/se_emoji.db`，路径以项目根目录为基准 |
| `AUTO_CREATE_TABLES` | 使用 `true`，启动时建立缺失的数据表 |
| `AI_SERVICE_KEY` | 填写另一段随机长字符串，与 AI 配置中的服务密钥一致 |
| `AI_DEVICE_ID` | 默认 `demo-device-01`，与 AI 配置中的设备标识一致 |
| `AI_ALLOWED_SESSION_IDS` | 填写允许 AI 访问的课堂 ID，以逗号分隔；留空表示不额外限制课堂列表 |
| `TEACHER_INVITE_CODE` | 设置教师自助注册邀请码；留空则关闭教师自助注册入口 |
| `ADMIN_INVITE_CODE` | 设置管理员自助注册邀请码；与教师邀请码分别配置 |
| `MANUAL_SLOT_SECONDS` | 默认 `30`，同一学生、课堂每个时间片最多提交一次；`0` 表示不限制 |
| `ACCESS_TOKEN_MINUTES` | 默认 `60`，用户访问令牌有效分钟数 |

可分别执行以下命令，为 `SECRET_KEY` 和 `AI_SERVICE_KEY` 生成不同的随机值，再填入配置文件：

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

后端优先读取当前终端已有的环境变量，再读取根目录 `.env`；修改配置后重启后端。`SECRET_KEY` 留空会生成进程临时密钥，重启后原令牌失效。真实 `.env`、服务密钥和运行数据库不提交源码仓库。

### 2.3 初始化演示数据

在项目根目录执行不带清库参数的初始化命令：

```powershell
.\.venv\Scripts\python.exe .\backend\scripts\seed_demo.py
```

脚本建立数据表，并创建管理员、教师、学生、课程、课堂名单和示例记录；检测到已有 `admin` 时跳过初始化，保留现有数据。初始化输出会列出账号和进行中课堂的实际 ID。

演示课堂时间需要更新时，执行：

```powershell
.\.venv\Scripts\python.exe .\backend\scripts\seed_demo.py --refresh
```

该命令调整“软件工程实践”“数据结构”演示课程下课堂的时间，并清除这些演示课堂的取消标记；用户和历史记录保留，记录观测时间不随课堂一起平移。刷新后可通过一次新的学生提交或 AI 采样观察实时变化。

### 2.4 构建 Web 页面

```powershell
Set-Location -LiteralPath '.\frontend'
npm install
npm run build
Set-Location -LiteralPath '..'
```

构建产物位于 `frontend/dist`。后端在启动时托管该目录，浏览器与后端使用同一地址。前端变更后重新构建并重启后端。

### 2.5 启动后端与访问系统

在项目根目录执行，并保持此终端运行：

```powershell
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

| 地址 | 内容 |
| --- | --- |
| `http://127.0.0.1:8000` | 三角色 Web 系统 |
| `http://127.0.0.1:8000/health` | 健康检查，正常返回 `status: ok` |
| `http://127.0.0.1:8000/docs` | Swagger 接口调试 |
| `http://127.0.0.1:8000/redoc` | 只读接口文档 |

后端终端按 `Ctrl+C` 停止服务。重启时继续使用原数据库与配置即可。

## 3 账号、登录与退出

### 3.1 初始化演示账号

| 角色 | 用户名 | 初始密码 |
| --- | --- | --- |
| 管理员 | `admin` | `Admin@2026` |
| 教师 | `teacher_zhang`、`teacher_li` | `Emoji@2026` |
| 学生 | `stu2021001` 至 `stu2021008` | `Emoji@2026` |

这些账号由初始化脚本创建，用于本地演示。

### 3.2 注册与修改密码

学生从登录页进入“学生注册”；教师进入“教师注册”并填写教师邀请码。管理员访问 `http://127.0.0.1:8000/#/register/admin` 注册并填写管理员邀请码，局域网替换主机地址。用户名须字母开头、3—32 位，仅含字母、数字和下划线；密码 8—64 位，同时包含字母和数字，邮箱为非必填。

新学生注册后，由管理员加入课堂名单才能提交反馈。教师注册后，由管理员在课程中指定其为授课教师。

Web 登录后点击右上角用户名 → “个人设置”，填写原密码和新密码；成功后使用新密码重新登录。修改密码、启用或停用账号会使该账号原令牌立即失效。

### 3.3 退出方式

Web 使用右上角“退出登录”，桌面端使用“退出登录”或关闭窗口，清除当前客户端保存的令牌。关闭 Web 标签页本身不会清除浏览器保存的登录信息。

退出客户端不等于服务端撤销已签发的 JWT；令牌到期、修改密码或账号启停后，服务端才按规则拒绝原令牌。

## 4 学生操作

### 4.1 Web 端反馈与历史

1. 登录后打开“我的课堂”，查看课程、教师、班级、教室、时间和状态。
2. 在进行中课堂点击“提交反馈”，选择开心、平静、低落、生气、惊讶、害怕或厌恶之一，点击“确认提交”。
3. 查看提交结果与服务器记录时间；失败时按提示检查名单、课堂状态或时间片限制。
4. 打开“我的记录”，按课程和日期筛选、分页查看本人手动记录；从课堂的“查看记录”进入时自动限定该课堂。

### 4.2 桌面端

另开 PowerShell，进入项目根目录后启动：

```powershell
.\.venv\Scripts\python.exe .\desktop-client\client.py
```

连接局域网后端时指定地址：

```powershell
.\.venv\Scripts\python.exe .\desktop-client\client.py --base-url http://192.168.1.10:8000
```

学生登录后，在“我的课堂”刷新列表，选中进行中课堂并点击“进入反馈”，或双击该课堂；在“提交反馈”页签点击表情。通过“我的记录”翻页或刷新历史；“修改密码”页签填写原密码、新密码和确认密码，成功后返回登录页。
## 5 教师操作

### 5.1 课堂看板与学生明细

进入“课堂看板”，先选课程再选课堂，查看课堂信息和更新时间；在“参与学生”中点击“查看记录”，查看该生在当前课堂的手动记录。

| 指标 | 含义 |
| --- | --- |
| 手动反馈次数 | 手动记录条数，同一学生可在不同时间片多次提交 |
| 参与学生数 | 有手动反馈的学生去重数，不等于到课人数 |
| 名单覆盖率 | 参与学生数除以名单人数；空名单显示“不适用” |
| AI 有效观察次数 | 通过阈值的观察结果数，同一人跨帧可重复计数 |
| 最近有效样本 | 最近一条 AI 记录的观测时间，无新记录不直接等于设备离线 |

看板将手动和 AI 分区展示。新记录通过 WebSocket 触发刷新；页面可见时每 3 秒轮询，离开页面停止。

### 5.2 多维统计

进入“多维统计”，选择课程、班级、日期范围和来源后查询，查看记录数、参与人数、类别分布和时间趋势。结果仅包含本人所授课程，教师页面不提供 CSV 导出。

看板类别占比分来源计算，多维统计按当前筛选记录总数计算；查看单一来源时选择“手动”或“AI”。跨课堂统计不计算覆盖率，AI 观察次数不作为学生人数或单一情绪得分。

## 6 管理员操作

| 页面 | 操作步骤与规则 |
| --- | --- |
| 用户管理 | 按角色、状态、关键字查询；“新建用户”创建教师或学生；启停账号后原令牌失效；不能停用当前管理员或最后一名启用管理员 |
| 课程与课堂 | 新建课程并指定启用教师 → 新建未来课堂，填写班级、教室、北京时间起止时间和 AI 阈值 → 在“名单”中搜索、勾选学生并保存 |
| 课堂维护 | 未开始时可编辑或取消；开始后课堂信息、阈值和名单冻结。结束须晚于开始；仅启用学生可加入名单，重复保存自动去重 |
| 课堂看板 | 可切换所有课程和课堂，查看与教师端相同的指标和学生明细 |
| 记录明细 | 按课程、班级、日期、来源、表情筛选并分页查看；表格含时间、课程、班级、学生、表情、来源、置信度、设备和事件编号，AI 学生显示“匿名” |
| 多维统计 | 设置筛选条件并查询图表，点击“导出 CSV”下载相同条件下的记录；空结果保留表头，单次最多 50000 行 |
| 审计日志 | 分页查看建号、账号启停、建课、改课堂、名单和导出等操作；保持“全部操作”可查看所有类型，或按页面提供的操作类型查询 |

排课时先设置未来开始时间并保存名单，再等待课堂开始；结束时间为提交区间的右边界，达到结束时刻即停止接收新反馈。课堂取消后学生不能提交。

## 7 AI 服务操作

### 7.1 下载模型与建立配置

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe .\ai-worker\scripts\download_models.py
if (-not (Test-Path -LiteralPath '.\ai-worker\config.yaml')) {
    Copy-Item -LiteralPath '.\ai-worker\config.example.yaml' -Destination '.\ai-worker\config.yaml'
}
```

下载脚本将模型写入 `ai-worker/models/` 并校验 SHA256：

- `face_detection_yunet_2026may.onnx`
- `facial_expression_recognition_mobilefacenet_2022july.onnx`

编辑 `ai-worker/config.yaml`：

| 字段 | 设置 |
| --- | --- |
| `api_base` | 后端地址，如 `http://127.0.0.1:8000`；局域网使用主机实际 IP |
| `service_key` | 与后端 `AI_SERVICE_KEY` 完全一致 |
| `device_id` | 与后端 `AI_DEVICE_ID` 一致，默认 `demo-device-01` |
| `session_id` | 实际进行中课堂 ID |
| `camera_index` | 摄像头序号，通常从 `0` 开始 |
| `video_path` | 摄像头采集时为 `null`；使用回放时填写操作者已有视频路径 |
| `sample_interval` | 采样间隔，默认 `3.0` 秒 |
| `threshold` | 使用 `null` 跟随课堂阈值；后端始终按课堂阈值复核 |
| `detector_model, expression_model` | 保留样例中的模型路径，相对配置文件目录解析 |

AI 进程不自动读取项目根目录 `.env`。配置文件中的密钥、设备和地址可分别被当前终端的 `AI_SERVICE_KEY`、`AI_DEVICE_ID`、`AI_API_BASE` 环境变量覆盖；命令行 `--session-id` 再覆盖配置中的课堂 ID。修改 YAML 后若仍读取旧值，先检查该终端是否已有对应环境变量。

### 7.2 确定课堂并启动摄像头

初始化输出会给出进行中课堂 ID。自行创建的课堂，可在 `/docs` 使用管理员账号调用登录接口，复制 `access_token` 到“Authorize”，再查询 `GET /api/v1/sessions`，以 `status=ONGOING` 的结果确认课堂 `id`。

另开终端进入项目根目录，以下 `1` 替换为上述实际课堂 ID：

```powershell
$sessionId = 1
.\.venv\Scripts\python.exe .\ai-worker\run.py --config .\ai-worker\config.yaml --session-id $sessionId --camera 0
```

摄像头模式须将 YAML 的 `video_path` 保持为 `null`；非空回放路径优先于摄像头。预览窗口显示分类和置信度，日志显示过滤、接收、重复及拒绝数量。教师或管理员同时打开对应课堂看板，在 AI 分区查看新增观察。

### 7.3 回放与退出

回放视频由操作者自行提供，仓库中的模型下载脚本不会生成课堂视频。将以下示例路径替换为实际存在的视频；命令会先检查文件：

```powershell
$sessionId = 1
$replayPath = 'D:\Videos\classroom.mp4'
if (-not (Test-Path -LiteralPath $replayPath -PathType Leaf)) {
    throw '请将 replayPath 改为实际存在的回放视频路径。'
}
.\.venv\Scripts\python.exe .\ai-worker\run.py --config .\ai-worker\config.yaml --session-id $sessionId --video $replayPath
```

回放会在预览和日志中标明输入类型。需要不显示窗口时追加 `--no-display`；只处理一帧时追加 `--once`，该帧仍须通过人脸检测和阈值校验才会生成记录。

预览窗口按 `q`，或终端按 `Ctrl+C` 退出；课堂结束时进程停止采集。课堂未开始时默认等待，追加 `--no-wait` 可立即退出。
