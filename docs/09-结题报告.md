## 1 项目概述

本项目实现一个课堂情绪反馈系统。学生在课堂进行中主动选择表情符号记录感受；AI 进程从摄像头或回放视频采样，检测人脸、分类表情并按阈值过滤后匿名上报；教师查看所授课堂的实时看板、分布与参与情况；管理员管理用户、课程、课堂与名单，按多维条件统计并导出 CSV。

系统采用 B/S 与 C/S 混合架构：Web 端承担浏览器访问，桌面客户端承担 C/S 通道，AI 进程独立部署。后端采用 Controller、Service、Repository 分层，前端采用修改版 MVC 与 MVVM 组合的职责划分。

项目的重点不在模型训练，而在完整的数据流程与软件工程实现：身份与权限、课堂状态、名单、幂等、统计口径、导出安全、AI 可靠性与可复现部署。

## 3 系统设计

### 3.1 总体架构

系统由四部分组成：

1. Web 客户端：Vue 3 单页应用，三角色页面，构建产物由后端托管。
2. 桌面客户端：Python tkinter，覆盖登录、选课、提交、历史与改密，构成 C/S 通道。
3. 后端：FastAPI，Controller、Service、Repository 三层，统一响应与异常处理。
4. AI 进程：OpenCV 与 ONNX Runtime，采样、检测、分类、过滤与上传。

数据库默认 SQLite 并开启 WAL，可选 MySQL 8。三端通过同一 REST 契约通信，AI 使用独立服务密钥。

### 3.2 修改版 MVC

修改点有三条：

1. 视图在浏览器内渲染，不使用服务端模板。
2. 控制器职责前移到前端页面控制器与后端 Controller 两处。
3. 前端不直接访问数据库，AI 不承载业务操作。

前端 `controllers` 存放管理端页面控制器：统计页的筛选、查询、导出，课程课堂页的建课、排人、取消。`composables` 存放学生反馈与教师看板的状态逻辑，作为 MVVM 的 ViewModel。后端 Controller 只做参数绑定与响应组装，业务规则集中在 Service。

### 3.3 关键设计决策

| 决策 | 理由 | 代价 |
| --- | --- | --- |
| SQLite 默认 | 免安装、可复现，降低验收故障点 | 高并发写入能力有限，需 MySQL 作为可选形态 |
| 轮询加 WebSocket 信号 | 推送只触发拉取，避免两套统计口径 | 仍有一次网络往返延迟 |
| 名单冻结 | 保证历史统计口径稳定 | 课堂开始后不能临时加人 |
| 手动与 AI 分区 | 两者分母不同，合并会误导 | 页面信息量增加 |
| AI 匿名 | 避免人脸识别与隐私风险 | 无法按学生分析 |
| 桌面客户端用标准库 | 无第三方 GUI 依赖，验收机可直接运行 | 界面表现力有限 |

## 4 关键实现

### 4.1 认证与权限

密码使用 Argon2id 加盐哈希，长度与字符组合有服务端校验。JWT 有效期 60 分钟，携带 `auth_version`；改密、停用、启用均递增版本，旧令牌立即失效。角色校验在依赖层完成，数据归属在 Service 层追加：教师查询强制 `Course.teacher_id = 当前用户`，学生查询强制 `user_id = 当前用户` 且来源为 MANUAL。

教师与管理员注册使用独立邀请码，比较使用恒定时间算法。邀请码未配置时接口关闭。管理员不能停用当前账号或最后一个启用管理员，避免系统失去管理入口。

### 4.2 课堂状态与名单

课堂状态不落库，由服务器时间与取消标记推导，区间为左闭右开 `[start_at, end_at)`。未开始时允许修改时间、班级、教室、阈值与取消；开始后冻结。名单整体替换在单事务内完成，先删除再插入，联合唯一约束兜底。

班级名在写入与查询时做 NFKC 归一与空白压缩，降低“计科 2101”与“计科２１０１”被统计为两个班级的风险。该字段仍是自由文本，不引入独立班级实体。

### 4.3 手动反馈的幂等与时间片

提交请求携带 `event_id`、`session_id`、`emotion`，用户与观测时间由服务端赋值。同一学生同一课堂同一时间片只允许一条记录，时间片长度由 `MANUAL_SLOT_SECONDS` 配置，默认 30 秒，0 表示不限制。

并发下可能同时触发 `event_id` 唯一约束与时间片唯一约束。Service 在冲突后回滚并重查：同一事件内容一致返回原记录并标记 `duplicate`，内容不一致或时间片被占用返回 409。这一处理避免了“重试被误判为冲突”的常见问题。

### 4.4 统计口径

手动反馈次数按记录数统计，参与学生按 `user_id` 去重，覆盖率仅在名单非空时计算。AI 有效观察次数按通过阈值的人脸结果统计，同一人跨帧会重复计数。手动与 AI 分布分别以各自总数为分母，分钟趋势按观测时间分桶，空桶补 0。

列表、统计与导出复用同一套 `EmojiFilters`，教师归属由 Service 追加，避免各写查询导致口径分裂。

### 4.5 CSV 导出安全

导出使用标准库 `csv` 处理引号与换行，输出 UTF-8 BOM。对以 `= + - @ \t \r` 开头或前导空白后接这些字符的文本前置单引号，防止电子表格执行公式。单次最多 50000 行，导出行为写入审计日志。

### 4.6 实时看板

前端每 3 秒轮询一次，上一请求完成后再发起下一次。记录入库后后端通过 WebSocket 推送 `emoji.created`，前端收到后立即拉取一次看板。推送只传信号，不传统计数据，保证推送与查询不会出现两套口径。连续失败显示“更新失败”与上次成功时间，保留旧数据。

### 4.7 AI 推理链路

AI 进程按 3 秒间隔取帧，使用 YuNet 检测人脸与五点，按标准五点对齐到 112×112，转换为 RGB 并归一化到 `[-1, 1]`，输入 MobileFaceNet 表情模型。模型输出 7 维 logits，代码执行 softmax 后取最大类得分作为置信度。

低于课堂阈值、尺寸过小或超过每帧上限的人脸被丢弃并计数，不生成“中性”假数据。事件入队后批量上传，网络失败按 1、2、4、8 秒退避，单事件最长保留 30 秒；401/403 立即停止，422 整批丢弃，逐事件拒绝不重试。

模型选择经过实测：OpenCV 5.x 的 ONNX Runtime 引擎要求动态输入，因此使用 `face_detection_yunet_2026may.onnx`；表情模型输出为 logits 而非概率，随机输入下存在负值且和不为 1，因此必须执行 softmax。类别顺序取自官方封装，与字母序不同。

## 5 AI 集成与局限性

### 5.1 已完成

- 模型文件可下载并校验 SHA256，许可为 MIT 与 Apache-2.0。
- 摄像头与回放输入共用接口，回放会在界面与日志中标注。
- 检测、对齐、分类、过滤、上传、入库全链路可运行。
- 回放图片产生一条匿名 AI 记录，字段为 `user_id=NULL`、`source=AI`、置信度 0.7366、设备与模型版本正确。
- 单元测试覆盖阈值边界、类别顺序、softmax 分布、上传重试与整批丢弃。

### 5.2 局限

1. **置信度不是准确率**。得分是模型 softmax 输出，未经本项目校准，不等于判断正确的概率。结题报告与界面均不把它称为准确率。
2. **未测真实准确率**。没有建立带人工标签的测试集，不报告准确率、召回率或混淆矩阵。公开模型在 RAF-DB 上的 88.27% 不能等同于本系统在教室场景的效果。
3. **跨帧重复**。同一人在连续采样中会被多次计数，AI 观察次数不是独立学生人数，不能用来计算“多少学生开心”。
4. **表情不等于感受**。模型识别的是面部表情，学生可能掩饰、疲劳、走神或光线不足；结果不能解释为真实心理状态、知识掌握或教学质量。
5. **环境敏感**。光照、遮挡、姿态、口罩、个体差异与训练数据分布都会影响结果。演示时应说明这些条件，不挑选有利画面冒充普遍效果。
6. **单人单摄像头**。首版一台设备关联一节课堂，不支持多摄像头拼接与身份跟踪。
7. **真实摄像头未在本机验证**。本机无摄像头，链路用回放图片验证；演示前必须在演示机复核，记录实际光照与识别情况。
8. **回放输入不等于现场采集**。使用回放时界面显示 `REPLAY INPUT`，日志标注“回放输入”，不得在视频中冒充现场。

### 5.3 隐私

原始帧只在内存中使用，检测后释放；不写盘、不缓存特征向量、不记录可识别个人的信息。上传内容只有事件 ID、时间、表情类别、置信度、设备与模型版本。演示前需征得在场人员同意，摄像头画面只在本机预览。

## 10 经验与改进

1. **先验证再承诺**。AI 模型输出语义、OpenCV 版本兼容与路径编码都是实际遇到的问题，提前用最小脚本验证比在文档中假设更可靠。
2. **文档必须与代码同步**。审核发现前端控制器目录为空、README 仍写“前端待开发”，说明文档自检不能代替实现核对。
3. **演示流程要确定**。依赖课堂自然开始会让录制受秒级时序影响，改为管理员调整开始时间后，流程可重复。
4. **统计口径要写死**。手动次数、参与人数、AI 观察次数分开定义，避免答辩时被追问“这个百分比是什么的分母”。
5. **隐私设计要前置**。AI 只上报匿名结果，既降低风险，也让统计口径更诚实。

后续改进方向：补充真实课堂样本与人工标签，评估误判；引入 Alembic 管理迁移；将限流与队列替换为 Redis；补充浏览器端到端测试与性能压测；在 MySQL 与 Docker 形态完成回归后再写入部署文档。

## 11 结论

项目完成了课堂情绪反馈的核心闭环：三角色认证与权限、课程课堂名单、手动反馈、教师看板、多维统计与导出、AI 匿名入库、桌面客户端与完整文档。后端 51 项、AI 20 项测试通过，端到端流程与回放 AI 链路有实际运行证据。

项目仍存在真实摄像头未验证、MySQL 与 Docker 未回归、浏览器自动化与性能测试缺失等限制。这些限制已在测试报告、部署说明与本报告中明确标注。系统适合作为课程演示与软件工程实践样本，不适合作为心理诊断、教学评价或学生情绪排名的工具。
