## 1 审核结论

方案 v1.1 在需求边界、权限矩阵、统计口径与 AI 可靠性方面的设计达到课程要求，可以作为开发基础。但该版本的部分结论已被后续实现推翻，另有一项指导书明确要求的功能缺失，若按原文提交会在验收时被直接指出。

本次审核将结论定为**修订后通过**。方案升级为 v2.0，作为实施基线；本意见第 4 节列出必须完成的修正，第 5 节列出代码层缺陷，第 6 节给出更新后的实现约定，第 7 节给出截至 11 月 14 日的冻结顺序。

需要强调评分结构：指导书第十节给出的权重为需求与设计文档 15%、核心功能完成度 20%、架构与代码质量 15%、AI 集成与数据流程 10%、测试与质量保障 10%、平时签到 30%。文档与架构合计 30%，与核心功能同权。因此“代码能跑”不足以覆盖评分项，文档、分层结构和测试证据必须与代码同步交付。

## 4 必须修正项

### 4.1 管理员注册缺失

指导书 2.1 将“管理员注册、登录”列为主要权限，2.2 管理端第一条即“管理员注册、登录”。方案 1.2 与审核意见第一版将其改为“仅初始化脚本创建”，理由是管理员可停用账号、导出全量数据。安全考虑成立，但与验收表述冲突，答辩时无法用“更安全”解释缺失。

修正办法：保留脚本初始化为主路径，同时开放受控的管理员注册。请求携带 `role=ADMIN` 时，必须同时提供与环境变量 `ADMIN_INVITE_CODE` 一致的邀请码；该变量为空时接口返回 422，注册入口在页面上隐藏。邀请码使用 `hmac.compare_digest` 比较，注册成功写入审计日志。默认配置不设置邀请码，保证开箱状态不存在可注册的管理员入口。

验收口径：配置邀请码后，使用正确邀请码可注册管理员并登录；错误邀请码返回 422；未配置邀请码时返回 422 且不产生账号。该行为写入测试报告与用户手册。

### 4.2 C/S 通道缺位

指导书第三章要求“C/S + B/S 混合架构”，架构示意中客户端与管理端并列。方案第一版自认简化为纯 Web，以 AI 进程充当客户端。AI 进程是采集工具，不承载学生或教师的业务操作，不能作为 C/S 客户端。

修正办法：增加 `desktop-client` 桌面客户端，使用 Python 标准库 tkinter，覆盖登录、选择课堂、提交表情、查看个人历史四条主流程，直接调用同一套 REST 接口。客户端不引入第三方 GUI 依赖，保证验收机可运行。代码规模控制在 400 行以内，作为 C/S 通道的实现证据，并在概要设计中说明它与 Web 端共用 API 契约。

### 4.3 修改版 MVC 缺少代码支撑

方案 5.3 与审核意见第一版 3.8 都声称管理端采用客户端 MVC、学生端按 MVVM 组织，但仓库中 `frontend/src/controllers` 与 `frontend/src/composables` 均为空目录，页面逻辑全部写在 `.vue` 单文件组件的 `<script setup>` 中。文档声称的结构在代码中不存在，属于架构项的直接扣分点。

修正办法：至少完成两组真实抽取，使目录与文档对应：

1. 管理端：把多维统计页的筛选、查询、导出逻辑抽到 `controllers/statisticsController.js`；把课程课堂页的建课、排人、取消逻辑抽到 `controllers/sessionController.js`。
2. 学生端与教师端：把反馈提交逻辑抽到 `composables/useFeedback.js`；把看板轮询、WebSocket、学生明细抽到 `composables/useDashboard.js`。

抽取后，`.vue` 只保留模板与对控制器/组合式函数的调用。文档按“Model 为前端状态模块、View 为模板、Controller 为页面控制器与路由守卫”的表述同步修订，不把 Vue 框架本身等同于 MVC。

### 4.4 AI 推理进程未实现

`ai-worker` 目录只有 README，没有采集、检测、分类、过滤、上传代码。指导书 AI 集成占 10%，且 9.2 验收要求“AI 服务可从视频分析情绪并写入数据库”。这是当前最大的功能缺口。

修正办法：按方案第 8 章实现以下模块，并以真实摄像头或回放视频完成一次端到端入库：

| 模块 | 职责 | 验收点 |
| --- | --- | --- |
| `capture` | 摄像头与视频文件输入，按间隔取帧 | 摄像头不可用时明确报错，回放输入标记来源 |
| `detect` | YuNet 人脸检测 | 无人脸时不生成记录，计数 |
| `classify` | 表情 ONNX 推理，读取 7 维得分 | 确认输出是 logits 还是概率，softmax 只做一次 |
| `filter` | 阈值过滤、类别映射 | 低于课堂阈值丢弃并计数 |
| `uploader` | 批量上传、1/2/4/8 秒退避、30 秒上限 | 网络失败重试，逐事件拒绝不重试 |
| `main` | 参数解析、课堂上下文、优雅退出 | 课堂结束停止采集 |

模型文件不入仓库，提供下载脚本、SHA256、许可说明与本地缓存目录。正式演示前完成模型预下载，演示过程不联网。

### 4.5 数据库脚本与部署材料缺失

方案 6.2 以 MySQL 8 为唯一数据库，实际实现默认 SQLite WAL，审核机未安装 MySQL。两者必须统一表述，不能把未验证的形态写成已验证。

修正办法：

1. 以 SQLite 作为开发与演示默认形态，文档明确写出。
2. 提供 `db/schema_mysql.sql`，字段、索引、约束与 SQLAlchemy 模型一致，差异仅限自增主键与字符集。
3. 提供 `db/seed.sql` 作为可选演示数据脚本，或在文档中说明使用 `backend/scripts/seed_demo.py`。
4. 提供 `docker-compose.yml` 与后端 Dockerfile，标注为可选部署形态；若未在容器内完成回归，文档必须写明“配置已提供，未完成容器内全量回归”。

### 4.6 演示数据会过期

`seed_demo.py` 以执行时刻为基准生成“进行中”课堂，默认窗口为开始前 15 分钟至开始后 45 分钟。若在 11 月 12 日录制视频，而初始化在 10 月 29 日执行，演示时所有课堂均已结束，学生无法提交，看板无实时数据。

修正办法：为 `seed_demo.py` 增加 `--refresh` 参数，仅平移三节演示课堂的时间，使其相对当前时刻重新处于“未开始、进行中、已结束”三种状态，不删除用户和历史记录；同时提供 `--reset` 用于完全重建。演示脚本第一步固定为执行 `--refresh`。

### 4.7 演示脚本的时序风险

方案 11.1 要求“录制第 1 分 40 秒后课堂自然开始”。课堂开始后名单冻结，若管理员在此之前未保存名单，整段演示作废；若操作延迟，课堂已开始但名单为空，学生无法提交。该脚本把成败交给秒级时序，不适合一次录制成功的要求。

修正办法：采用确定性流程。录制前创建一节开始时间在 10 分钟后的课堂并保存名单；录制时管理员把开始时间改为当前时间前一分钟，课堂立即进入进行中，名单已就绪。该操作属于“未开始课堂允许调整时间”的正常权限，不修改代码。脚本按此重写，并在用户手册中说明。

### 4.8 接口路径与指导书示例不一致

指导书第五章给出的是示例路径，不要求逐字一致，但当前实现与示例差异较多，答辩时容易被追问“为什么找不到 `/api/admin/statistics`”。

修正办法：保留现有路径为规范路径，同时增加兼容别名，指向同一处理函数：

| 指导书示例 | 现有规范路径 | 兼容别名 |
| --- | --- | --- |
| `GET /api/admin/dashboard/realtime` | `/api/v1/dashboard/realtime` | `/api/v1/admin/dashboard/realtime` |
| `GET /api/admin/statistics` | `/api/v1/statistics` | `/api/v1/admin/statistics` |
| `GET /api/emoji/statistics` | `/api/v1/statistics` | `/api/v1/emoji/statistics` |
| `POST /api/admin/sessions/{id}/schedule` | `PUT /api/v1/admin/sessions/{id}/members` | `POST /api/v1/admin/sessions/{id}/schedule` |

别名在 OpenAPI 中标注“兼容路径”，文档说明规范路径与别名的关系，避免两套口径。

## 8 风险与降级

| 风险 | 触发条件 | 应对 |
| --- | --- | --- |
| 摄像头不可用或光线不足 | 演示机无摄像头或识别不稳定 | 使用回放视频并在界面与日志标注“回放输入”，不冒充现场采集；文档如实说明 |
| 模型输出语义不符 | 输出维度不是 7 类或无法取得得分 | 换用可返回得分的 ONNX 模型，保持接口契约不变 |
| 推理速度不足 | 单帧处理超过 3 秒 | 采样间隔降为 5 秒，降低输入分辨率，限单人演示 |
| 人员投入不足 | 里程碑连续未达成 | 删除第三优先级，保留第一优先级与文档 |
| 管理员注册引入风险 | 邀请码泄露 | 默认不配置邀请码；生产环境使用长随机值并定期更换；审计日志记录注册行为 |
| 演示数据过期 | 录制时课堂已结束 | 录制前执行 `--refresh`，并在脚本中固定该步骤 |

降级顺序：额外图表与美化、Docker 与 CI、MySQL 实机回归、WebSocket 之外的实时优化。真实 AI、手动反馈、教师可见性、名单管理、统计导出、权限控制与可运行代码始终保留。
