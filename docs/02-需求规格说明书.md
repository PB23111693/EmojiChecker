## 1 引言

### 1.1 编写目的

本文档定义系统的角色、功能、非功能需求与验收标准，作为设计、开发、测试和结题验收的共同依据。文档描述的是当前版本已经实现或明确列入交付范围的能力；未实现的内容在“范围外”与“已知限制”中单独说明，不写成已完成。

### 1.2 项目范围

系统面向课堂场景，提供三类业务角色与一个独立 AI 进程：

- 学生在课堂进行中主动提交表情符号，查看本人历史记录。
- 教师查看所授课堂的实时看板、表情分布、参与情况与学生明细。
- 管理员管理用户、课程、课堂与名单，按多维条件统计并导出 CSV。
- AI 进程从摄像头或回放视频采样，检测人脸、分类表情，按阈值过滤后匿名上报。

系统不提供心理诊断、学生情绪排名、成绩预测、自动评价教师、教务系统对接、短信或邮箱找回密码、公网高可用部署。AI 结果是模型对表情的估计，不能解释为学生的真实心理状态或教学质量。

### 1.3 术语与缩写

| 术语 | 含义 |
| --- | --- |
| emoji | 界面上的表情符号，七类之一 |
| emotion | 情绪类别枚举：HAPPY、NEUTRAL、SAD、ANGRY、SURPRISED、FEARFUL、DISGUST |
| 课堂 / ClassSession | 一门课程在特定时间、班级、教室的一次授课 |
| 名单 / ScheduleUser | 课堂的参与学生集合，表示提交资格，不代表出勤 |
| 手动记录 | 学生主动提交的 emoji 记录，来源 MANUAL |
| AI 记录 | AI 进程上报的匿名分类结果，来源 AI，用户为空 |
| 时间片 | 同一学生同一课堂允许提交的最小时间间隔，默认 30 秒 |
| AT | 验收测试用例编号 |

## 2 总体描述

### 2.1 产品定位

一套可在普通电脑与局域网内演示的课堂反馈系统。Web 端承担 B/S 通道，桌面客户端承担 C/S 通道，AI 进程独立运行。首版支持一台设备关联一节进行中的课堂，不训练模型，不做人脸身份识别。

### 2.2 用户角色

| 角色 | 主要权限 | 数据范围 |
| --- | --- | --- |
| 学生 | 注册、登录、改密、提交表情、查看个人历史 | 仅本人手动记录与被安排的课堂 |
| 教师 | 登录、改密、查看所授课堂看板与统计、查看学生明细 | 仅本人所授课程 |
| 管理员 | 登录、改密、用户管理、课程课堂名单、统计、导出、审计日志 | 全部数据 |
| AI 进程 | 读取课堂配置、上报匿名分类结果 | 仅绑定设备与授权课堂 |

教师与管理员支持凭邀请码自助注册。邀请码由部署方在环境变量中配置，未配置时入口关闭。学生注册不需要邀请码，也不能指定角色。

### 2.3 运行环境

| 项目 | 要求 |
| --- | --- |
| 服务端 | Windows 10/11 或 Linux，Python 3.12，2 GB 以上内存 |
| 数据库 | 默认 SQLite（WAL），可选 MySQL 8 |
| 浏览器 | Chrome、Edge 等现代浏览器，支持 WebSocket |
| 桌面客户端 | Windows 或 Linux，Python 标准库 tkinter |
| AI 进程 | 摄像头或视频文件，OpenCV 5.0，ONNX Runtime 1.20，CPU 可运行 |
| 网络 | 本机或局域网；演示不依赖公网 |

### 2.4 约束与假设

- 课堂开始后时间、名单与 AI 阈值冻结，避免历史数据口径变化。
- 手动与 AI 记录分别统计，不合并为单一“班级情绪得分”。
- 原始人脸帧、视频与特征向量不落库、不入日志、不进仓库。
- 演示数据由脚本生成；录制前必须刷新课堂时间，避免课堂全部过期。
- 团队成员、学号与贡献比例由团队在贡献表中填写，系统不预置虚构数据。

### 3.1 FR01 认证与账号

- 学生注册只接受用户名、密码、可选邮箱，传入 `role=ADMIN` 或 `role=TEACHER` 而未提供邀请码时返回 422。
- 教师注册需要 `role=TEACHER` 与 `invite_code`，邀请码与环境变量 `TEACHER_INVITE_CODE` 一致。
- 管理员注册需要 `role=ADMIN` 与 `invite_code`，邀请码与环境变量 `ADMIN_INVITE_CODE` 一致；该变量为空时接口关闭。
- 密码长度 8 至 64，至少包含字母与数字，使用 Argon2id 加盐哈希。
- 登录返回 JWT 与过期时间；每次请求校验账号状态与 `auth_version`；改密、停用、启用均递增版本，旧令牌立即失效。
- 用户名唯一，格式为字母开头、字母数字下划线、3 至 32 位。

### 3.2 FR02 课程与课堂

- 管理员创建课程时指定一名启用状态的教师；同一教师下课程名唯一。
- 课堂字段包括课程、班级、教室、开始时间、结束时间、AI 阈值，默认阈值 0.6。
- 课堂状态由服务器时间推导：未开始、进行中、已结束；取消标记优先。
- 时间区间为左闭右开 `[start_at, end_at)`；结束时间必须晚于开始时间；接口时间必须带时区。
- 未开始的课堂允许修改时间、班级、教室、阈值与取消；开始后冻结。

### 3.3 FR03 名单

- 管理员整体保存名单，服务端在事务内替换，按课堂与用户联合去重。
- 只有启用状态的学生可以加入；不存在、非学生、已停用的用户返回 422。
- 名单为空时课堂仍可处于进行中，但所有学生都不能提交；该课堂不作为正式演示课堂。
- 名单表示提交资格，不表示出勤。

### 3.4 FR04 手动反馈

- 学生从“我的课堂”进入进行中的课堂，选择七类表情之一并确认。
- 服务端从登录身份确定学生 ID，校验课堂存在、名单、状态、时间片与幂等。
- 同一学生同一课堂同一时间片只允许一条记录；时间片长度由 `MANUAL_SLOT_SECONDS` 配置，默认 30，0 表示不限制。
- 请求包含 `event_id`、`session_id`、`emotion`；`user_id`、来源与观测时间由服务端赋值。
- 同一 `event_id` 重试且内容一致返回原记录并标记 `duplicate=true`；内容不一致返回 409。
- 并发冲突后按 `event_id` 重查，内容一致按幂等成功处理，不返回 409。

### 3.5 FR05 个人历史

- 学生只能查询本人手动记录；传入他人 `user_id` 不改变范围。
- 支持按课堂、课程、班级、日期范围与分页筛选。
- 默认每页 20 条，最大 100 条；按观测时间倒序。

### 3.6 FR06 教师查询

- 教师只能访问所授课程下的课堂；访问他人课堂返回 404，不泄露对象是否存在。
- 看板提供手动反馈次数、参与学生数、名单人数、覆盖率、类别分布、分钟趋势、AI 有效观察次数、阈值与最近有效样本时间。
- 参与学生列表可下钻到该生在本课堂的手动记录。
- 统计与导出接口同样追加教师归属条件。

### 3.7 FR07 实时看板

- 前端每 3 秒轮询一次；上一请求完成后再发起下一次；离开页面停止。
- WebSocket `/ws/dashboard` 在记录入库后推送变更信号，前端收到后立即拉取一次看板数据。
- WebSocket 只作触发信号，不承载业务数据，避免推送与查询两套口径。
- 连续失败显示“更新失败”与上次成功时间，保留旧数据；无记录显示“暂无数据”，不填充中性情绪。

### 3.8 FR08 多维统计

- 筛选维度：课程、班级、时间范围、来源、情绪类别。
- 指标：记录总数、手动次数、AI 观察次数、参与学生数、类别分布、分钟趋势。
- 分钟趋势按观测时间分桶，空桶补 0；跨天时横轴带日期。
- 跨课堂汇总只展示记录数与分布，不计算跨课堂覆盖率，避免不同名单人数直接平均。

### 3.9 FR09 CSV 导出

- 导出使用与页面相同的筛选参数，不另写查询。
- 字段包括记录 ID、课程、班级、课堂开始时间、学生账号、表情、来源、置信度、观测时间、接收时间、设备。
- 输出 UTF-8 BOM，Excel 可直接打开中文。
- 对以 `= + - @ \t \r` 开头或前导空白后接这些字符的文本前置单引号，防止公式注入。
- 单次最多导出 50000 行；导出写入审计日志。

### 3.10 FR10 AI 推理与入库

- AI 进程使用独立服务密钥 `X-AI-Service-Key`，不能使用用户令牌。
- 进程读取课堂配置，获得时间窗、阈值与七类枚举；设备标识必须与服务端配置一致。
- 采样间隔默认 3 秒；每帧最多处理 5 张人脸；最小人脸边长 48 像素。
- 检测使用 YuNet，分类使用 MobileFaceNet 表情模型；输出 7 维 logits，执行 softmax 后取最大类得分。
- 低于课堂阈值、尺寸过小、超过每帧上限的人脸丢弃并计数，不生成“中性”假数据。
- 上传批量不超过 100 条；网络失败或 5xx 按 1、2、4、8 秒退避；单事件最长保留 30 秒；队列上限 100，超限丢弃最旧事件并计数。
- 401/403 立即停止上传并提示配置错误；请求级 422 整批丢弃；逐事件拒绝不重试。
- 服务端再次校验密钥、设备、课堂状态、时间窗、阈值、枚举与事件唯一性；重复事件不重复入库。
- 原始帧只在内存中使用，不写盘、不缓存特征向量、不记录可识别个人的信息。

### 3.11 FR11 权限与审计

- 所有角色与数据归属判断在 service 层执行，前端隐藏菜单只用于导航。
- 关键操作写入审计日志：注册、登录失败、创建用户、停用账号、创建课程、创建/修改课堂、保存名单、导出。
- 审计日志只允许管理员查询；不记录密码、密钥或原始人脸数据。
- 统一响应结构 `{code, message, data, request_id}`；错误同时返回对应 HTTP 状态码。
- 登录与提交接口启用单进程滑动窗口限流；多进程部署的限制写入部署说明。

### 3.12 FR12 部署与文档

- 提供 `.env.example`、初始化脚本、README、部署说明、接口文档、测试报告、用户手册。
- 新环境按 README 可完成安装、初始化与启动；换机复现结果记录在测试报告。
- 提交包不包含虚拟环境、`node_modules`、数据库文件、真实密钥、个人数据与原始人脸视频。

### 3.13 FR14 桌面客户端

- 使用 Python 标准库 tkinter 与 urllib，无第三方 GUI 依赖。
- 覆盖登录、选择课堂、提交表情、查看历史、修改密码五条流程。
- 仅进行中课堂启用提交；非学生角色不能提交。
- 令牌只保存在内存，退出即清除；网络请求在后台线程执行，结果由主线程更新界面。

### 3.14 FR15 管理员记录明细

- 管理员在“记录明细”页面分页查看全部手动与 AI 记录。
- 支持按课程、班级、日期范围、来源与表情筛选，筛选条件与统计页保持一致。
- 表格显示观测时间、课程、班级、学生（AI 显示匿名）、表情、来源、置信度、设备与事件编号。
- 教师可通过“多维统计”查看所授课程图表，但不能导出 CSV；导出仅限管理员。

## 5 用例设计

### 5.1 UC01 学生提交反馈

| 项目 | 内容 |
| --- | --- |
| 参与者 | 学生 |
| 前置条件 | 账号启用并登录；已被安排到课堂；课堂进行中 |
| 主流程 | 进入我的课堂 → 选择进行中课堂 → 选择表情 → 确认提交 → 服务端写入 → 显示成功与服务器时间 |
| 异常流程 | 不在名单 403；课堂未开始/已结束/已取消 409；时间片内重复 409；`event_id` 冲突 409；登录过期 401 |
| 后置条件 | 生成一条 MANUAL 记录，看板与统计可见 |

### 5.2 UC02 教师查看课堂看板

| 项目 | 内容 |
| --- | --- |
| 参与者 | 教师 |
| 前置条件 | 登录；课堂属于本人所授课程 |
| 主流程 | 选择课程与课堂 → 加载看板 → 查看看板分区与趋势 → 点击参与学生查看明细 |
| 异常流程 | 他人课堂 404；无记录显示暂无数据；轮询失败显示更新失败并保留旧数据 |
| 后置条件 | 无数据写入 |

### 5.3 UC03 管理员排课与导出

| 项目 | 内容 |
| --- | --- |
| 参与者 | 管理员 |
| 前置条件 | 登录；教师与学生账号存在 |
| 主流程 | 创建课程 → 创建课堂 → 保存名单 → （课堂进行后）筛选统计 → 导出 CSV |
| 异常流程 | 教师角色不符 422；结束时间不晚于开始时间 422；开始后修改名单 409；空结果导出 0 行 |
| 后置条件 | 课程、课堂、名单与审计日志写入；导出文件下载 |

### 5.4 UC04 AI 分析与入库

| 项目 | 内容 |
| --- | --- |
| 参与者 | AI 进程操作者 |
| 前置条件 | 后端启动；AI 密钥与设备配置一致；课堂进行中；模型已下载 |

| 后置条件 | 生成匿名 AI 记录；不保存原始帧 |

## 6 数据需求

核心实体为 User、Course、ClassSession、ScheduleUser、EmojiRecord、AuditLog。所有 ID 使用 BIGINT，事件 ID 使用 UUID 字符串；时间统一存 UTC；枚举使用字符串加 CHECK 约束。详细字段、索引与约束见 `docs/04-数据库设计说明书.md`。

数据保留策略：

- 用户停用不物理删除，保留历史关联。
- 课程与课堂不提供物理删除接口，避免破坏历史统计。
- AI 记录不关联学生，不进入个人历史。
- 导出与统计不修改原始记录。

## 8 范围外与已知限制

1. 不开发 Android 原生客户端；移动端通过浏览器访问。
2. 不提供刷新令牌、找回密码、邮件或短信通知。
3. 不支持课程转交教师、多校区组织、复杂选课与考勤。
4. MySQL 8 只提供建表脚本与连接配置，未完成全量回归。
5. Docker 配置已提供，构建环境未安装 Docker，未完成容器内实测。
6. AI 模型未在本项目数据上校准，置信度不等于判断正确的概率；同一人跨帧会重复计数。
7. 浏览器端到端自动化测试未在本机执行；UI 以构建成功、接口契约核对与人工路径检查为准。
