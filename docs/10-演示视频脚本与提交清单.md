# 演示视频脚本与提交清单

项目：表情符号课堂情绪检查器系统
版本：2.0
编制日期：2026 年 10 月 29 日
视频时长：5 至 8 分钟，建议 7 分钟

## 1 录制前准备

### 1.1 环境检查

| 项目 | 检查内容 |
| --- | --- |
| 后端 | `http://127.0.0.1:8000/health` 返回 ok |
| 前端 | 已执行 `npm run build`，首页可打开 |
| 数据库 | 已执行 `seed_demo.py --refresh`，存在进行中课堂 |
| 摄像头 | AI 进程能打开并显示画面，光线充足 |
| 模型 | `scripts/download_models.py --check-only` 全部通过 |
| 账号 | 管理员、教师、两名学生均可登录 |
| 桌面客户端 | `client.py` 能启动并登录 |
| 屏幕 | 1920×1080，浏览器缩放 100%，关闭无关窗口与通知 |
| 音频 | 麦克风测试通过，环境安静 |

### 1.2 数据准备

1. 执行 `seed_demo.py --refresh`，确认演示课堂处于进行中。
2. 管理员新建一节开始时间在 10 分钟后的课堂，班级“计科2101”，保存 8 人名单，作为录制中“立即开始”的对象。
3. 准备两名学生账号：一名用于 Web 提交，一名用于桌面客户端提交，避免同一学生触发 30 秒时间片。
4. 若希望同一学生连续演示两次提交，可在录制环境把 `MANUAL_SLOT_SECONDS` 设为 0；文档与视频中说明生产建议值为 30。

### 1.3 录屏设置

- 分辨率 1920×1080，帧率 30，格式 MP4。
- 录制整个屏幕，鼠标移动平缓，点击前停顿半秒。
- 讲解语速适中，避免读代码。
- 不出现密码、`SECRET_KEY`、`AI_SERVICE_KEY` 的完整内容；登录时密码框显示圆点。

## 2 分镜脚本

### 2.1 0:00–0:35 项目与架构

| 画面 | 讲解要点 |
| --- | --- |
| 浏览器首页或架构图 | 项目名称、三类角色、Web 与桌面客户端、AI 进程、后端与数据库 |
| 简要切换目录 | 后端分层、前端控制器、AI 模块、文档目录 |

讲解：系统支持学生主动反馈、教师实时看板、管理员排课统计与 AI 匿名观察。四端共用一套 REST 接口，AI 只上报匿名分类结果。

### 2.2 0:35–1:30 管理员排课与开始课堂

| 画面 | 操作 |
| --- | --- |
| 管理员登录 | 打开“课程与课堂” |
| 展示课堂 | 选中已排好名单的未来课堂，展示班级、时间、名单人数 |
| 修改开始时间 | 点击“编辑”，把开始时间改为当前时间前一分钟，保存 |
| 状态变化 | 列表状态变为“进行中”，名单与阈值显示已冻结 |

讲解：名单在开始前保存，开始后冻结；这样演示不依赖课堂自然开始，流程可重复。名单表示提交资格，不代表出勤。

### 2.3 1:30–2:30 学生 Web 端提交与历史

| 画面 | 操作 |
| --- | --- |
| 学生 A 登录 | 进入“我的课堂”，展示进行中课堂 |
| 提交 | 进入反馈页，选择“开心”，确认提交 |
| 结果 | 显示“反馈已记录”与服务器时间 |
| 历史 | 打开“我的记录”，展示刚才的记录 |

讲解：服务端从登录身份确定学生，校验名单、课堂状态与时间片；重复提交使用同一事件编号，不会产生重复记录。

### 2.4 2:30–3:10 桌面客户端（C/S 通道）

| 画面 | 操作 |
| --- | --- |
| 启动客户端 | `python client.py`，学生 B 登录 |
| 课堂列表 | 展示课程、班级、时间、状态 |
| 提交 | 选择进行中课堂，点击“平静” |
| 历史 | 切换到“我的记录”，展示记录 |

讲解：桌面客户端使用标准库 tkinter，与 Web 共用同一套接口，构成 C/S 通道；令牌只保存在内存。

### 2.5 3:10–4:10 教师看板

| 画面 | 操作 |
| --- | --- |
| 教师登录 | 进入“课堂看板”，选择课程与课堂 |
| 手动区 | 展示反馈次数、参与学生、覆盖率与分布 |
| 学生明细 | 点击“参与学生”中的“查看记录” |
| 趋势 | 切换手动与 AI 趋势 |

讲解：反馈次数与参与人数分母不同；覆盖率是参与学生除以名单人数；手动与 AI 分区统计，不合并为单一得分。页面每 3 秒刷新，WebSocket 有新记录时立即拉取。

### 2.6 4:10–5:30 AI 摄像头与入库

| 画面 | 操作 |
| --- | --- |
| 启动 AI | 终端运行 `run.py`，窗口显示摄像头画面 |
| 人脸框 | 展示绿色框、类别与置信度 |
| 阈值说明 | 指出低分人脸不入库，界面与日志有计数 |
| 看板 | 切回教师看板，AI 区出现新记录与最近样本时间 |

讲解：YuNet 检测、五点对齐、MobileFaceNet 分类、softmax 取最大类；服务端按课堂阈值二次校验；原始帧不落盘，记录不含身份信息。若使用回放，必须展示 `REPLAY INPUT` 标记。

### 2.7 5:30–6:20 管理员统计与导出

| 画面 | 操作 |
| --- | --- |
| 多维统计 | 按课程、班级、日期、来源筛选 |
| 图表 | 展示分布与分钟趋势 |
| 导出 | 点击“导出 CSV”，用 Excel 打开 |
| 说明 | 指出中文正常、危险文本前置单引号 |

讲解：导出与页面使用同一筛选条件；UTF-8 BOM 保证 Excel 中文可读；公式前缀被转义，避免 CSV 注入。

### 2.8 6:20–7:00 工程质量与局限

| 画面 | 内容 |
| --- | --- |
| 测试 | 终端展示 `51 passed` 与 AI `20 passed` |
| 文档 | 快速展示需求、设计、数据库、接口、测试、部署、手册、报告 |
| 安全 | 展示学生访问管理接口返回 403，教师访问他人课堂返回 404 |
| 局限 | 口述 AI 置信度不是准确率、跨帧重复、真实摄像头条件、MySQL 与 Docker 未回归 |

讲解：项目重点是完整数据流程与软件工程实现；AI 结果不能解释为真实心理状态或教学质量。未完成项已在测试报告与结题报告中标注。

## 3 录制注意事项

1. 演示课堂必须在录制前已保存名单；开始后名单冻结，不能补人。
2. 修改开始时间属于“未开始课堂允许调整时间”的正常权限，不是绕过规则。
3. 同一学生 30 秒内只能提交一次；Web 与桌面演示使用不同学生，或把时间片设为 0 并在视频中说明。
4. AI 演示优先使用真实摄像头；光线不足时使用回放，并在画面与讲解中明确标注，不得冒充现场采集。
5. 密码、密钥、令牌不出镜；终端窗口先清屏，避免历史命令泄露密钥。
6. 不展示真实学生姓名、学号或可识别的人脸特写；演示账号为初始化数据。
7. 一次录制不追求完美，出现失败可保留并说明原因，或重录该段；最终视频剪辑后总时长控制在 5 至 8 分钟。

## 7 答辩可能被问到的问题

| 问题 | 回答要点 |
| --- | --- |
| 为什么用 SQLite 而不是 MySQL | 降低验收环境依赖；MySQL DDL 已提供，未完成回归，文档如实标注 |
| WebSocket 与轮询为什么同时存在 | WebSocket 只作变更信号，轮询负责断线恢复，避免两套统计口径 |
| AI 置信度是准确率吗 | 不是，是 softmax 得分，未经校准；未建立标注集，不报告准确率 |
| 为什么 AI 记录没有学生 | 避免人脸识别与隐私风险；统计口径是观察次数，不是学生人数 |
| 课堂开始后为什么不能改名单 | 保证历史统计分母稳定；需要调整时重建课堂 |
| 修改版 MVC 改在哪里 | 视图浏览器渲染、控制器前移到前后端两处、统一 REST 契约 |
| C/S 体现在哪里 | 桌面客户端覆盖学生主流程，与 Web 共用接口，AI 不算业务客户端 |
| 30 秒时间片如何保证并发 | 数据库唯一约束加冲突后重查，内容一致按幂等返回 |
| 未完成的部分 | 真实摄像头待演示机复核，MySQL 与 Docker 未回归，浏览器自动化与压测未执行 |
